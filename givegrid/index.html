The problem

Offices, hotels and event organisers throw away usable goods that NGOs are actively asking for. GiveGrid connects the two: donors list items, verified NGOs post needs, the platform ranks matches, and the whole handover is tracked from claim to pickup. One donation can be split between several NGOs.

The race condition

The course's hard requirement: 100 chairs, two NGOs each claim 70 at the same instant. A naive version reads "100 available" twice, approves both, and promises 140 chairs that don't exist.

A claim locks the donation and the need rows before reading them, then changes four rows in one transaction, all or nothing:

BEGIN;
SELECT * FROM donations WHERE id = ? FOR UPDATE;   -- second claimer waits here
SELECT * FROM needs     WHERE id = ? FOR UPDATE;
-- check quantity; if short, reply 409 with a counter-offer and reserve nothing
UPDATE donations SET available_quantity = available_quantity - ? ...;
UPDATE needs     SET remaining_quantity = remaining_quantity - ? ...;
INSERT INTO allocations ...;  INSERT INTO donation_events ...;
COMMIT;

History nobody can rewrite

Append-only history is enforced by MySQL itself, in two layers. The app's database account simply has no UPDATE or DELETE rights on the history table, and a trigger blocks changes even from an administrator:

-- as the app's account
UPDATE donation_events SET quantity = 0 WHERE id = 1;
ERROR 1142: UPDATE command denied to user 'givegrid_app'

-- as root
UPDATE donation_events SET quantity = 0 WHERE id = 1;
ERROR 1644: donation_events is append-only: UPDATE is not allowed

Claims are held for 48 hours; if the NGO doesn't confirm a pickup plan, a timer releases the items back to the donation, and the concurrency tests prove it releases them exactly once.

Errata

Our first concurrency test sent the two requests one after another. It passed against code with no locking at all, because nothing was ever concurrent. The professor caught it. The rewritten tests fire requests simultaneously, and removing FOR UPDATE now makes 5 of the 9 fail, which is the only evidence that a concurrency test tests anything.
